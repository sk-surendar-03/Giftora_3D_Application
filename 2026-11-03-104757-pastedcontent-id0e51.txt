  ## 5. Authentication architecture

  You can use one common authentication system:

  ```
  Customer Login ─┐
                  ├── Common Backend Authentication
  Admin Login ────┘
                         ↓
                   PostgreSQL users
                         ↓
                 Role-based authorization
  ```

  Roles:

  ```
  CUSTOMER
  ADMIN
  SUPER_ADMIN
  ```

  Admin frontend should have protected routes and admin-only API access.

  For your production architecture, use secure HTTP-only cookies where
  appropriate, with proper CORS, CSRF protection, and cookie configuration.

  ### Benefits

  - Deploy customer website independently.
  - Deploy admin dashboard independently.
  - Update backend without rebuilding both frontends, provided the API contract
  remains compatible.
  - Maintain one database and centralized business logic.
  - Scale frontend applications separately.
  - Keep admin UI isolated from customer UI.
  - Share types and validation definitions through `packages/shared`.

  My recommendation: Use three independently deployable applications—Customer
  Frontend, Admin Frontend, and Backend API—with one shared PostgreSQL database
  and a separate STL worker.

  This structure is scalable and maintainable for your project.
